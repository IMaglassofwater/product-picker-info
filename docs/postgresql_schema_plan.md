# PostgreSQL Schema Plan

## Scope

Migration includes every historical row, not only qualified opportunities: all Products (currently 653), processed URLs, candidates, AI results, analyses, specificity, metric snapshots, pipeline/source runs, feedback, and re-evaluation requests.

## Type Mapping

| SQLite | PostgreSQL |
|---|---|
| `INTEGER PRIMARY KEY AUTOINCREMENT` | `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| bounded scores/counts | `INTEGER` |
| flag integers (`0/1`) | `BOOLEAN` |
| timestamp `TEXT` | UTC `TIMESTAMPTZ` |
| JSON array/object `TEXT` | `JSONB` |
| ordinary `TEXT` | `TEXT` |

## Complete Table Inventory

| Table | PostgreSQL constraints and conversions |
|---|---|
| `products` | `url UNIQUE`; `raw_data`, flags/signals `JSONB`; created time `TIMESTAMPTZ` |
| `processed_projects` | `url UNIQUE`; pushed time `TIMESTAMPTZ` |
| `micro_innovation_candidates` | `candidate_id UNIQUE`, `source_url UNIQUE`; `signals JSONB` |
| `ai_triage_results` | `UNIQUE(candidate_id, provider, model)`; arrays `JSONB`; boolean deep flag |
| `deep_analysis_results` | versioned composite unique key; `result_json JSONB` |
| `software_analysis_results` | versioned composite unique key; `result_json JSONB` |
| `product_metric_snapshots` | `product_id BIGINT REFERENCES products(id)`; `metric_data JSONB` |
| `pipeline_runs` | text primary run ID; UTC timestamps and status |
| `pipeline_source_runs` | run foreign key; `UNIQUE(run_id, source_platform)`; boolean failure flag |
| `specificity_results` | `UNIQUE(candidate_id, rule_version)`; flags `JSONB` |
| `user_product_feedback` | `UNIQUE(entity_type, entity_id)`; UTC timestamps |
| `re_evaluation_requests` | preserve full pending/history queue |

Candidate foreign keys absent from legacy SQLite should be added only after orphan validation. Add indexes for source/date, candidate/provider/model, run time, and pending queue queries.

## Safe Sequence

1. Supply credentials only through `POSTGRES_DATABASE_URL` in an explicitly approved migration session.
2. Run `python scripts/migrate_sqlite_to_postgres.py` without `--execute` and archive every table count.
3. Create schema transactionally, copy in dependency order, reset identities, and compare counts/unique keys.
4. Validate orphans, timestamps, JSON, and representative Web reads.
5. Switch `DATABASE_URL` only after parity and a rollback checkpoint.

Phase 9.8B implements the PostgreSQL schema, bounded connection pool, production-only copy, and post-copy count checks. No real PostgreSQL connection or migration was executed while preparing the package.
